# LeanVault 1.1.1

- Fixed saving and editing logins failing with HTTP 422 on Vaultwarden 2026.x. Cipher writes now send
  `encryptedFor` (the signed-in user's id), which the server requires.

- **Allowed symbols** in the password generator starts with the generator's existing set,
  `!@#$%^&*_-+=`, instead of every ASCII symbol. You can still edit it and add any ASCII symbol.
- Fixed **Allowed symbols** showing "undefined". The popup now validates the generator settings it
  receives, so a background worker still running older code can no longer leave the field empty.

## Test this build

Reload LeanVault at `chrome://extensions` (the reload button, not just reopening the popup), confirm
**1.1.1**, open Generator, and check that Allowed symbols shows `!@#$%^&*_-+=`.
