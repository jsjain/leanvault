# LeanVault 1.1.0

- The copy button (⧉) on a vault row opens a floating menu: **Copy username**, **Copy password**,
  and **Copy verification code** when the login has an authenticator key. Row menus (⧉ and ⋮) now
  float over the list instead of expanding the row; click outside, press Escape or scroll to close.
- **Delete** moves a personal login to the trash, as in the official clients. It is in the ⋮ menu
  and on the login's detail view, and needs a second click to confirm. Protected logins ask for the
  master password first. Restore or purge trashed items from the web vault.
- Logins can store an authenticator (TOTP) key. Enter a Base32 secret or an `otpauth://totp/` URI
  in **Authenticator key (TOTP)** when adding or editing a login. When editing, leave it blank to
  keep the current key. Invalid keys are rejected before anything is sent to the server.
- With website integration on, LeanVault tells username, password and 2FA code fields apart. Focusing
  a 2FA field lists the matching logins that have a key, and choosing one fills the current code.
  The seed never leaves the background worker.
- **Update existing login** from the page prompt no longer clears notes or favorite, and no longer
  replaces the login's websites with the current page URL. A changed password is kept in password
  history (last five), as in the official clients.
- The password generator has an **Allowed symbols** list. It starts with every printable ASCII
  symbol. For a site that accepts only some symbols, type just those (for example `!@#$`). Letters,
  digits and spaces are dropped, and an empty list means all symbols. The list also applies to
  passwords generated from a website's password field.
- Server errors now name the request and include the server's reason, for example
  `PUT /api/ciphers/<id> failed with HTTP 422: ...`.

## Known limits

- 2FA inputs split into one box per digit are not filled. Fill the first box by hand.
- A stored TOTP key cannot be removed from LeanVault yet. Use the web vault.

## The intermittent 422 on save

Not yet resolved. Vaultwarden returns 422 only when it cannot parse the request body into its cipher
model, and the payload this extension sends matches that model in every release from 1.30 to
current, so the failing field could not be found from code. Errors now name the request and the
server's reason. The matching Vaultwarden log line names the rejected field.

## Test this build

1. Reload LeanVault at `chrome://extensions` using the generated `dist/` folder, refresh open
   website tabs, and confirm **1.1.0**.
2. In the popup, click ⧉ on a row and copy each option. Confirm the row does not change height.
   Delete a test login (click Delete twice) and confirm it appears in the web vault's trash.
3. Edit a login, paste a TOTP secret, save, and confirm the detail view shows a changing code.
4. On that site's 2FA page, focus the code field and fill the code from the menu.
5. In Generator, set Allowed symbols to `_-` and confirm generated passwords use only those.
6. Change a saved password on a site and choose **Update**. Confirm notes, favorite, extra websites
   and the TOTP key are still on the item.
